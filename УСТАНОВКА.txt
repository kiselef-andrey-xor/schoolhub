ШКОЛА HUB — УСТАНОВКА НА SYNOLOGY БЕЗ SSH И БЕЗ «КОДА НАСТРОЙКИ»
=================================================================

Редакция архива от 13.10.2026. Все грабли предыдущих попыток обойдены:
порты 5432/8000 наружу не публикуются, пути сборки абсолютные (/volume2/...),
тома БД и секретов — новые (старые «битые» не используются), ключ сессий задан
явно, Владелец создаётся сам при первом старте.

УЧЁТНЫЕ ДАННЫЕ ВЛАДЕЛЬЦА (создаются автоматически на первом старте):
    e-mail:   admin@schoolhub.local
    пароль:   Nas#School-2026!
Хотите свои? ДО первой сборки откройте docker-compose.yml в корне этой папки
и поправьте одну строку `command:` у сервиса backend:
    --email 'ваш@email' --password 'ВашПароль' --name 'ФИО' --school 'Школа №'
(пароль — не короче 8 символов; кавычки вокруг значений сохраните).

ШАГ 1. Удалить старое
    Container Manager → Проект → schoolhub → Удалить
    (если спросит «удалить контейнеры» — согласиться).
    Тома удалять НЕ нужно: редакция использует новые имена
    (db_v2, uploads_v2, secrets_v2), старые просто останутся на диске неиспользованными.

ШАГ 2. Заменить файлы проекта
    File Station → /volume2/docker/schoolhub → удалите старую папку `app`
    (в ней только исходники; все данные жили в томах, ничего не потеряется).
    Загрузите туда же архив schoolhub-nas-fixed.zip → ПКМ → «Извлечь здесь».
    Должно получиться: /volume2/docker/schoolhub/app, а внутри —
    backend, frontend, docker-compose.yml и этот файл.

ШАГ 3. Собрать проект
    Container Manager → Проект → Создать.
    Имя проекта:  schoolhub
    Путь:         /docker/schoolhub/app
    Файл compose: docker-compose.yml в корне папки (подставится сам).
    Далее → Готово. Первая сборка на ARM-модели занимает 5–12 минут —
    это нормально, прогресс виден в карточке проекта.

ШАГ 4. Войти
    Когда три контейнера (schoolhub-db, schoolhub-backend, schoolhub-frontend)
    станут «Выполняется» и «Исправно», откройте в браузере:
        http://<адрес-NAS>:8080
    Будет СРАЗУ форма входа (никакой «Первоначальной настройки» и кодов).
    Введите e-mail и пароль Владельца из шапки этого файла.
    После входа смените пароль: аватар → «Мой профиль».

КАК ПОНЯТЬ, ЧТО ВСЁ ПОШЛО КАК НАДО (журнал schoolhub-backend):
    «✅ Готово. Учётная запись Владельца создана»   — владелец создан;
    «Starting SchoolHub API (env=prod)»             — API поднят;
    при повторных стартах вместо создания будет «В системе уже есть
    активных Владельцев: 1. Ничего не меняю» — это норма.

ЕСЛИ ЧТО-ТО НЕ ТАК
    • Порт 8080 занят другим сервисом: в docker-compose.yml у frontend
      замените "${HTTP_PORT:-8080}:80" на "${HTTP_PORT:-8090}:80" и пересоберите.
    • Журналы: Container Manager → Контейнер → нужный → «Журнал»;
      скриншот журнала = половина диагностики.
    • Файл deploy/synology/docker-compose.yml — копия корневого;
      в мастере всегда выбирайте корневой.

ОБНОВЛЕНИЕ В БУДУЩЕМ (тоже без SSH)
    Скачать свежий архив проекта → заменить содержимое папки `app`
    (сохранив ваши правки строки `command:` и SECRET_KEY) →
    Container Manager → Проект → Действие → Пересобрать.
    Данные (БД, загрузки, сессии) лежат в томах и обновлением не затрагиваются.
